# CLAUDE.md

## Overview

This repository analyses match-up data from the HYPERNETS in-water radiometry station(s) in France, comparing HYPERNETS-derived water-leaving reflectance (RHOW / ρw) against satellite ocean-colour sensors. **All four sensor families are wired end-to-end and have populated `output/`/`figures/`**: Sentinel-3 OLCI (S3A/S3B), MODIS-Aqua (AQUA), VIIRS (SNPP/JPSS1/JPSS2), and PACE-OCI (PACE). See `sensor_grid()` in `code/0_functions.R` for the authoritative sensor_Z → sensor_Y mapping.

**Sites: MAFR** (Gironde Estuary mouth — highly turbid) and **THFR** (a lagoon — clear-water comparison site to MAFR). The code (`sensor_grid()`, `global_scatterplot()`) detects sites via `available_sites()` automatically.

**Derived THFR sites:** `THFR_NE`, `THFR_poly`, and `THFR_pixel` are independent re-analyses of the same underlying THFR match-ups, each isolating one candidate fix for THFR's poor match-up quality: `THFR_NE` restricts to the NE quadrant of the inner 3×3 pixel grid, `THFR_poly` restricts to a hand-drawn clean-water polygon, and `THFR_pixel` applies no spatial filter at all (isolating the effect of the shared per-pixel QC gates from the two spatial filters). All three are first-class sites alongside MAFR/THFR — registered in `available_sites()`'s candidate list, generated by `code/1_matchups_single.R` before `process_sensor()` runs, and never replacing THFR anywhere in the pipeline. See `db_export_matchups_site()` in `code/0_functions.R` below.

This is a plain collection of R scripts (no package structure, no `DESCRIPTION`/`renv.lock`, no test suite), **numbered by pipeline run order** (`0_functions.R`, `1_matchups_single.R`, `2_outliers.R`, `3_sensitivity.R`, `4_matchups_global.R`, `5_figures.R`). Run scripts interactively/line-by-line in R, RStudio, or Positron from the repository root — several sections are commented-out exploratory/diagnostic code left in place intentionally (e.g. ad hoc checks at the end of `code/4_matchups_global.R`).

## Manuscript context

This codebase supports a manuscript targeting *Frontiers in Remote Sensing*, in the same Research Topic as its scientific/site precursor, **Doxaran et al. 2024** ("Validation of satellite-derived water-leaving reflectance in contrasted French coastal waters based on HYPERNETS field measurements", doi:10.3389/frsen.2023.1290110), which validated HYPERNETS at Berre lagoon (moderately turbid) and the Gironde Estuary/MAFR (highly turbid) against S2-MSI, L8/9-OLI, S3-OLCI, and Aqua-MODIS with multiple atmospheric-correction algorithms. This project reuses Doxaran et al. 2024's **site-contrast framing** (turbid MAFR vs. clear-water THFR, replacing their Berre lagoon site) but adopts the richer **statistical/technical methodology** (`base_stats()`'s Model II/SMA regression, Pahlevan-style log-space Bias/Error, MRD/MARD) developed in a separate, unpublished "in review" manuscript (Schlegel et al., working title "Hyperspectral field and satellite radiometric matchups in oligotrophic waters") describing a moving-vessel Tara HyperBOOST campaign — that paper is a technical/methods precursor only, not a site precursor (it studies oligotrophic open-ocean water, not French coastal sites). See `manuscript/roadmap.md` for the full literature synthesis and step-by-step plan, and `manuscript/track-changes.md` for a running log of repo changes made while developing this manuscript.

## Data dependency

The raw match-up `.csv`/`.sql` files this code reads are **not stored in this repo**. They are generated by an external tool, `Hypernets_matchups`, and read from a fixed local path pattern:

```
~/pCloudDrive/Documents/OMTAB/HYPERNETS/FR/<site_name>/RHOW_HYPERNETS_vs_<sat_name>/
```

(built by `file_path_build()` in `code/0_functions.R`). Running the full pipeline requires this external data to be present locally; it cannot be reconstructed from this repo alone.

## Running the code

No build/lint/test commands — this is exploratory analysis code executed with `Rscript` or interactively. Source the six scripts in numbered order from the repository root:

```r
source("code/0_functions.R")        # shared library -- always first
source("code/1_matchups_single.R")  # per-file matchup stats
source("code/2_outliers.R")         # outlier screening -> meta/satellite_outliers.csv
source("code/3_sensitivity.R")      # matchup-protocol sensitivity checks (optional but recommended)
source("code/4_matchups_global.R")  # per-wavelength global stats -> output/global_stats_*.csv
source("code/5_figures.R")          # final figures -> figures/
```

All scripts assume the working directory is the repository root (paths like `"output/..."`, `"meta/..."`, `"figures/..."` are relative).

## Pipeline order

The scripts are **numbered by run order**, driven by file dependencies (later stages read `.csv` outputs written by earlier stages):

1. **`code/0_functions.R`** — shared library, sourced by everything else. Never run standalone.
2. **`code/1_matchups_single.R`** — first regenerates the three derived THFR sites (`db_export_matchups_ne()`/`db_export_matchups_poly()`/`db_export_matchups_pixel()`, one loop per site across all four sensor families), then runs `process_sensor(sensor_Z)` in matchup mode for all four sensor families: computes per-file match-up stats → `output/matchup_stats_RHOW_<sensor_Z>.csv` and `output/matchup_noQC_stats_RHOW_<sensor_Z>.csv` (files failing the time/distance QC gate, see `process_sensor()`'s use of `site_diff_time_limit()` below).
3. **`code/2_outliers.R`** — semi-manual outlier screening, active for **all four sensor families** (OLCI, MODIS, VIIRS, OCI), across every site including the three derived THFR sites. Uses a satellite pixel-variance CV gate (`sat_var_check()`): OLCI/MODIS/VIIRS use `cv_limit_choice = 30` (set at the top of the script); OCI uses a hard-coded 50% threshold (lines 209–211, bypassing `cv_limit_choice`) as a temporary workaround while all THFR PACE files have anomalously high CVs — see Bug 8 in `manuscript/upstream-data-bugs.md`. A previous `Error_50 >= 100` gate and a prospective RMSE-based gate are left in as commented-out placeholders (not currently applied) in case either is reinstated later. Combines all four sensors' flagged files into `meta/satellite_outliers.csv`. **Must run before `4_matchups_global.R`**, which reads that file. Note: even the standard `cv_limit_choice = 30` gate can legitimately remove 100% of a site/sensor combination's matchups — see Bug 10 (THFR/JPSS2).
4. **`code/3_sensitivity.R`** — empirically justifies the match-up protocol's time-window and distance-window choices (distance sanity check against the per-sensor `dist_limit` ceiling; time-window sensitivity plot + trend test per site, justifying `site_diff_time_limit()`'s MAFR/THFR split; before/after comparison of `daily_closest_matchup()`). Not read by any other script, so safe to skip in a quick production run, but should be re-run whenever MAFR or THFR data change materially.
5. **`code/4_matchups_global.R`** — `process_sensor(sensor_Z, "global")` for all four sensor families: aggregates match-ups per wavelength → `output/global_stats_RHOW_<sensor_Z>.csv`, combined into `output/global_stats_all.csv`. Reads `meta/satellite_outliers.csv` (written by step 3) via `global_stats()`.
6. **`code/5_figures.R`** — reads the QC'd `output/` and `meta/` files to build final figures into `figures/`: the per-family global scatterplot stacks (MODIS/VIIRS/OLCI/OCI), Figure 1 (MAFR/THFR station map from `meta/station_in_situ.csv`), Figure 3 (HYPERNETS hyperspectral spectrum vs. satellite band-equivalent RHOW for one representative matchup date), Figure 4 (per-satellite HYPERNETS-vs-satellite scatterplots for that same date), Figure 11 (error/bias matrix heatmap faceted by sensor family), and Fig S1 (PACE OCI Error/Bias barplots across all wavelengths).

All four sensor families (OLCI, MODIS, VIIRS, OCI) are wired end-to-end for the MAFR and THFR sites. No code changes needed for the core pipeline itself, though see the site-specific time-window note below.

## Core architecture (`code/0_functions.R`)

Sensor naming has three tiers used consistently across the codebase:
- `sensor_Z` — sensor family / mission group, e.g. `"OLCI"`, `"OCI"`, `"VIIRS"`, `"MODIS"`.
- `sensor_Y` — specific platform/version within a family, e.g. `"S3A"`, `"S3B"`, `"S3_all"`, `"PACE"`, `"VIIRS_N"`/`"VIIRS_J1"`/`"VIIRS_J2"`, `"AQUA"`.
- `sensor_X` — the reference/in-situ system, generally `"HYPERNETS"` (column-named `"Hyp"` inside loaded data frames).

`sensor_grid()` and `W_nm_out()` map `sensor_Z` → `sensor_Y` list and → the fixed waveband set to compare, respectively. `colour_nm_func()` defines the plotting colour palette per `sensor_Y`, keyed by waveband label — note the code comments flag this palette as needing per-satellite-specific colour bands (see the note in `code/5_figures.R`), so don't assume today's palette choices are final.

Function groups, in read order in `0_functions.R`:
- **Utilities**: `file_path_build()`, `load_matchup_mean/long/var()` (parse the semicolon-delimited match-up CSVs; `load_matchup_mean` averages replicate scans and keeps exactly 2 sensor rows per file — mismatches raise a warning), `proc_HYPERNETS_L1C()` (parses HYPERNETS L1C NetCDF files), `sat_var_check()` (per-file satellite pixel variance), `available_sites(sat_name)` (checks disk for a given satellite's `MAFR`/`THFR`/`THFR_NE`/`THFR_poly`/`THFR_pixel` data folders; used by `sensor_grid()`/`global_scatterplot()` so a site is included automatically once its data folder exists), `site_diff_time_limit(site_name)` (site-specific match-up time-window limit in minutes — **MAFR = 15, THFR = 30**, mirroring Doxaran et al. 2024's Gironde/Berre split; see below), `site_rhow_limit(site_name)` (added 2026-09-03 — site-specific RHOW plausibility ceiling, MAFR = 0.25/THFR = 0.05, derived from the empirical max HYPERNETS RHOW observed per site; applied as a QC gate to both Hyp and satellite values), `sensor_resolution_km(sensor_Y)` (added 2026-09-03 — nominal per-sensor nadir pixel resolution in km, used to derive per-sensor distance QC ceilings), `daily_closest_matchup(df, site_name)` (added 2026-07-10 as `daily_average_matchups()`, **replaced 2026-09-03** with closest-in-time selection instead of averaging — same-day HYPERNETS scans and satellite overpasses are not independent measurements of the same water, so only the temporally-nearest pairing per calendar day is retained rather than blended).
- **Derived-site export**: `db_export_matchups_site(sensor_Z, site_name, pixel_filter_fn, file_tag, db_path)` is the shared driver behind all three derived THFR sites — reads raw per-pixel matchups directly from the SQLite database (`db_matchup_pixels()`), applies the whole-matchup time/distance/RHOW/negative-value QC gates (using `site_rhow_limit()`/`sensor_resolution_km()`, hardcoded to THFR's own policy regardless of `site_name`), then applies a site-specific `pixel_filter_fn` (`pixel_filter_ne_inner3x3`, `pixel_filter_clean_water`, or `pixel_filter_none`) before writing new per-matchup CSVs via `write_matchup_csv_ne()` into a new site folder. `db_export_matchups_ne()`/`db_export_matchups_poly()`/`db_export_matchups_pixel()` are one-line wrappers; adding a further derived site needs only a new `pixel_filter_*()` function plus one more wrapper.
- **Statistics**: `base_stats(x_vec, y_vec)` is the central stats function — computes RMSE, MAPE, MSA, ordinary and log-log linear slope, Model II (SMA) regression with 95% CI via `lmodel2`, and Pahlevan-style median relative Bias/Error in log space (25th/50th/75th percentiles). Returns an all-`NA` row when fewer than 2 valid (positive, non-NA) paired observations exist, or `NA` Model-II fields when either vector has zero variance (flat NIR bands). Called symmetrically in both directions (X→Y and Y→X) by `process_global_wavelength()`. Note: `base_stats()` only removes ≤ 0 values; HYPERNETS observations with RHOW > 1 (physically impossible, Bug 3) are not removed here — see the `Hyp > 1` gotcha below.
- **Match-up processing**: `process_matchup_file()` computes pairwise stats between all sensor combinations within one match-up file; `global_stats(site_name, sensor_Y, daily_average = TRUE)` aggregates across all files per wavelength, applying the outlier list from `meta/satellite_outliers.csv`, the pre-defined `W_nm_out()` waveband set, and (if `daily_average = TRUE`) `daily_closest_matchup()`; `process_sensor(sensor_Z, stat_choice = "matchup", daily_average = TRUE)` is the top-level driver, writing both matchup-level and global-level CSVs. `daily_average = TRUE` is canonical throughout: `global_stats()`'s default, `process_sensor()`'s default, and the four explicit calls in `4_matchups_global.R` all agree. Because `global_stats()` builds its file list from `output/matchup_stats_RHOW_<sensor_Z>.csv` (written by the matchup-mode QC gate below) before ever calling `daily_closest_matchup()`, day-level selection only ever runs on matchups that already passed the site's `diff_time`/`dist_limit` QC gate — nothing failing that gate reaches this step. **Time/distance QC gate:** distance now uses a per-sensor `dist_limit = 3 × sensor_resolution_km(sensor_Y)` ceiling (changed 2026-09-03 from a single flat 10 km ceiling used for every site, which had accommodated a known pixel-extraction offset in THFR PACE data — see Bug 7 in `manuscript/upstream-data-bugs.md`; for most other site–sensor combinations distances remain well under 1 km in practice). Time uses **`site_diff_time_limit(site_name)`** — MAFR = 15 min, THFR = 30 min — mirroring Doxaran et al. 2024's Gironde (±15 min) vs Berre (±30 min) split, justified empirically in `code/3_sensitivity.R`.
- **Plotting**: `plot_matchup_*()` family for per-file diagnostics, `plot_global_nm()`/`global_scatterplot()` for the final 1:1 scatter figures with Model II regression lines and CI bands, `global_scatterplot_stack()` for multi-panel composites, `global_scatterplot_waveband()` for per-waveband scatterplots faceted with site as point shape/colour, `plot_matrix_error()` for Figure 11's error/bias matrix heatmap (uses `tidyr::complete()` so a site/sensor combination with zero surviving matchups, e.g. THFR/JPSS2 — Bug 10 — still renders as a labelled grey `NA` cell rather than silently disappearing from the axis).

## Known repo-specific gotchas

- `.gitignore` intentionally lists exception rules after their governing globs — don't reorder without checking pattern precedence.
- `figures/` contains the per-family global scatterplot stacks (MODIS/VIIRS/OLCI/OCI), the per-waveband scatterplot stacks, plus Figures 1, 3, 4, 11, and S1 produced by `code/5_figures.R` (see the pipeline-order entry above for what each contains).
- **`5_figures.R` has an `if (!interactive()) quit()` guard** (mirroring the identical guard in `4_matchups_global.R`) right after the global scatterplot/waveband sections. A plain `Rscript code/5_figures.R` run therefore regenerates only those scatterplot stacks, **not** Figures 1/3/4/11/S1 — those require genuinely interactive execution (R console, RStudio, Positron) or shadowing `interactive <- function() TRUE` in the calling session before sourcing the file.
- The outlier CV gate is **not uniform across sensors**: OLCI/MODIS/VIIRS use `cv_limit_choice = 30` (top of `code/2_outliers.R`); OCI uses a hard-coded 50% threshold as a temporary workaround for Bug 8 (`manuscript/upstream-data-bugs.md`) — all THFR PACE files currently exceed 30%, likely because the pixel is extracted 5–8 km from the station (Bug 7). Both thresholds are placeholders pending re-extraction of the THFR PACE data. Even the standard 30% gate can legitimately remove 100% of a site/sensor combination (THFR/JPSS2 — Bug 10), which is a real QC outcome, not a bug in the gate itself.
- `daily_closest_matchup()` (added 2026-09-03, replacing `daily_average_matchups()`) picks the single closest-in-time matchup per calendar day rather than averaging same-day matchups together. After this selection, the `file_name` column is dropped (multiple candidate files collapse to one day-record); as a result the `n_clean`/`n_no_out` columns in the global stats CSVs count *files* that passed QC, while the `n` column from `base_stats()` counts *days* — these will differ when multiple same-day matchups exist. Keep that distinction in mind when interpreting matchup counts in the manuscript.
- **`Hyp > 1` filter gap:** the `Hyp <= 1` filter (Bug 3 workaround) is applied inside `global_scatterplot()` before plotting, but **not** inside `global_stats()` before computing statistics. `base_stats()` removes ≤ 0 values but not > 1 values. If any MAFR matchups contain HYPERNETS RHOW > 1 at any waveband, those observations will influence the statistics CSVs but not the figures — check and add the filter inside `global_stats()` if needed (see roadmap open item 11).
- **A row present but `NA` differs from a row absent.** A waveband can show `NA` in Figure 11/the stats CSVs for two distinct reasons: (1) the row exists but `base_stats()` returned an all-`NA` row because fewer than 2 valid positive paired observations remained at that waveband (e.g. THFR/JPSS1 at 411/445 nm — most matchup days have negative satellite RHOW at those blue bands), or (2) the site/sensor combination has zero surviving matchups at all (e.g. THFR/JPSS2 — Bug 10), which `plot_matrix_error()`'s `tidyr::complete()` now backfills into a labelled grey cell for every sensor family (not just OCI, as before 2026-09-03).
